OAFISH GRASS RUNTIME v0.9.2 - START HERE
========================================

1) DOWNLOAD the latest OGR release.

2) INSTALL THE PLUGIN:
   X-Plane 11\Resources\plugins\OafishGrassRuntime\win_x64\OafishGrassRuntime.xpl

3) INSTALL THE SHARED GRASS LIBRARY ONCE:
   Copy the whole OafishGrass_Library folder to:

   X-Plane 11\Custom Scenery\OafishGrass_Library\

   Keep that scenery pack enabled in scenery_packs.ini.

4) IN ANY AIRPORT PROJECT / WED:
   - Choose Forest Tool
   - Resource: OafishGrass/ogr_grass.for
   - Draw the grass Area polygon exactly where grass is allowed
   - Holes are supported
   - Set WED Density as desired
   - Save and Export Scenery Pack

   You DO NOT need to copy grass_A.obj / grass_B.obj / grass_C.obj or the grass
   textures into every airport anymore. They live once in OafishGrass_Library.

5) START X-PLANE.
   OGR finds the shared library provider, scans exported uncompressed scenery
   DSFs for OafishGrass/ogr_grass.for, and builds one shared runtime area cache
   inside OafishGrass_Library/OafishGrass/ogr_areas.json.

6) RAIN / WET GRASS:
   - OGR reads X-Plane precipitation/rain datarefs automatically.
   - Wetness builds quickly while rain is active and dries gradually afterward.
   - Wet blades react more heavily to wind, prop wash, jet blast and traffic wake.
   - Full wetness slightly reduces normal bend amplitude and damps fast changes,
     while tire flattening can still reach the normal approximately 90 degrees.
   - Dry wheel tracks recover in about 5.5 seconds.
   - Fully wet wheel tracks can remain visible for about 32 seconds after the
     tire leaves. Intermediate wetness smoothly interpolates between those times.
   - A wheel that is still physically on the grass keeps it pinned regardless
     of whether the aircraft is moving or parked.

   Useful Log.txt messages:
     [OGR] Wet grass response armed: ...
     [OGR] Wet grass active: blade response is heavier and tire tracks now recover more slowly

7) HELICOPTER ROTOR WASH (v0.9.2):
   - Native X-Plane rotorcraft are detected from the aircraft rotor-clutch flag.
   - XP11 rotor speed now prefers sim/flightmodel/engine/POINT_tacrad, which is
     the flight-model prop/rotor angular-speed array used by native helicopters.
   - If POINT_tacrad is not useful, OGR falls back to flightmodel2 prop speed,
     cockpit prop RPM, then turbine N2 as a last operating-rotor fallback.
   - OGR uses the largest prop-disc area as the main rotor and reads POINT_XYZ
     when available so the radial field is centered on the actual rotor hub
     instead of only the aircraft CG.
   - A low hover pushes grass radially outward from the main rotor in 360 degrees.
   - The old fixed-wing/prop rear cone is fully faded inside the rotor-dominant
     region, so front/left/right/back grass should respond to the main rotor.
   - The v0.9.2 radial footprint is stronger and wider near the helicopter while
     still weakening with height and stopping above about 35 m.
   - A small rotational swirl is added according to rotor direction.
   - Rotor power follows rotor RPM plus helicopter collective. X-Plane's prop
     ratio/prop ratio all values are used because those are also helicopter
     collective controls.
   - The rotor system targets the USER aircraft and a single/main-rotor
     approximation. Tandem/coaxial multi-disc placement and online helicopter
     rotor wash are future extensions.
   - Rotor wash is live-only; it is disabled while X-Plane Replay is active.
   - No new scan over all 10,000 streamed grass candidates is added.

   Useful Log.txt messages:
     [OGR] Helicopter rotor-wash detector armed: ...
     [OGR] Helicopter rotor wash active: main rotor source=POINT_tacrad, index=N, RPM ratio=..., collective=..., diameter=N m; radial 360-degree flow overrides the legacy rear cone nearby

8) ONLINE / AI TRAFFIC GRASS INTERACTION:
   - X-Plane 11.50+ TCAS target arrays are read only; OGR does not acquire,
     override, move or modify IVAO/VATSIM/AI traffic.
   - Compatible traffic providers that publish targets to X-Plane TCAS can
     disturb nearby grass with estimated engine/prop wash.
   - Ground traffic can also flatten grass under estimated tire positions.
   - TCAS does not expose each remote tire coordinate, so OGR estimates one
     nose-wheel point plus left/right main-gear points from aircraft class.
   - Light prop, turboprop, normal jet and heavy-jet footprints are different.
   - Moving traffic flattens grass in its travel direction; parked traffic uses
     aircraft heading and keeps grass down while weight-on-wheels remains true.
   - When traffic leaves, recovery uses the same dry/wet recovery system.
   - Traffic wheel flattening is used only when X-Plane provides the TCAS
     weight-on-wheels array; OGR does not guess wheel contact for airborne traffic.
   - Default scan interval: 0.10 s; nearby target budget: 24.

   Useful Log.txt messages:
     [OGR] TCAS/online traffic grass interaction armed ...
     [OGR] TCAS traffic detected: N nearby target(s) can now disturb OGR grass
     [OGR] TCAS traffic wheel flattening active: N ground aircraft mapped to M virtual tire contact(s)

9) USER AIRCRAFT WHEEL TRACKS:
   - A tire physically touching grass drives the contacted blades toward about 90 degrees.
   - The grass remains flat even if the aircraft stops on top of it.
   - Movement is used to remember the natural flatten direction.
   - v0.9.2 locks hard crush-direction reversals while the same grass clump is
     still flattened. This removes the visible left/right alternating flicker
     when a clump is equally close to two nearby gear contacts.
   - Gradual direction changes are still allowed, so turning/taxi tracks do not
     become permanently locked to the first heading.
   - Recovery begins only after the tire moves away or loses ground contact.
   - Dry recovery: about 5.5 seconds.
   - Fully wet recovery: about 32 seconds.

10) AFTER EDITING WED:
   - Save and Export Scenery Pack again
   - Restart X-Plane, or use:
     Plugins > Oafish Grass Runtime > Reload WED/DSF grass areas

11) LARGE AREAS / LOD:
   - Candidate grass follows the camera automatically
   - Near animated ring: about 600 m
   - Mid/far sparse rings continue out to about 2000 m
   - Default candidate budget: 10000
   - Active XPLM instances remain capped at 1600
   - Spatial bins + active-only animation remain enabled

12) LEGACY / FALLBACK WORKFLOW:
   WED-Starter/OafishGrass is still included. It can be copied into an airport
   scenery and BUILD_GRASS_AREAS.cmd can still be used for compressed/unsupported
   DSFs. The preferred workflow is the shared library above.

13) REPLAY:
   - Fly/taxi normally first so OGR records history
   - User-aircraft prop RPM / jet power / weather wind are recorded at 20 Hz
   - Enter X-Plane Replay and scrub inside the recorded window
   - Grass uses recorded prop wash / jet blast / wind
   - History window is up to about 20 minutes
   - Online traffic effects are live-only; OGR does not invent historical
     IVAO/VATSIM traffic positions during X-Plane replay.
   - Wetness currently follows the live/current weather state rather than being
     stored as a separate historical replay channel.
   - Helicopter rotor wash is live-only and is disabled in replay.

- Weather wind: ON

- Wetting response time constant: about 18 s

- Fully wet tire-track recovery: about 32 s

- User jet N1/thrust wash: ON
- User helicopter rotor wash: ON when native rotor datarefs identify a rotorcraft
- Rotor-wash maximum modeled height: about 35 m
- User wheel flattening: ON, holds while parked
- Crush-direction anti-flicker: ON
- TCAS/online traffic wash: ON
- TCAS/online traffic virtual wheel flattening: ON when weight-on-wheels is available
- Traffic update: 0.10 s
- Traffic target budget: 24
- Replay-aware user engine/wind history: ON
- Max active grass: 1600
- Max streamed candidates: 10000
- No shadow / no black grass cards retained

IMPORTANT:
The library .for resource is used for WED authoring and OGR metadata. OGR reads
Area forest polygons from exported DSFs and draws the real animated grass. SSA
is not required.
